# Medivyx Medical Care — Demo Website System Requirements

The goal of this demo should be to make the owner think: **“This is not just a website; this is how customers would actually find and interact with us.”**

Because the public information around Medivyx is limited, the demo should use **verified/general claims only** and make uncertain business details easy to replace later.

## 1. Product Vision

### Product name

**Medivyx Medical Care**

### Product type

Modern healthcare + pharmacy website and digital customer experience.

### Primary objective

Help people in Roysambu and surrounding areas:

**Discover Medivyx → Understand services/products → Find location → Contact → Request medicines/services → Become a returning customer**

### Demo objective

The demo should prove five things:

1. Medivyx can look like a serious, established healthcare brand.
2. Customers can find what they need quickly.
3. Customers can contact the business without friction.
4. The business can showcase medicines, healthcare products and services.
5. The website can later evolve into a full digital pharmacy platform.

# 19. Accessibility Requirements

Build it properly from the beginning.

### Must have

- WCAG-conscious contrast
- keyboard navigation
- visible focus states
- semantic HTML
- accessible buttons
- accessible form labels
- alt text
- screen-reader-friendly navigation
- no information conveyed by color alone
- large enough touch targets
- reduced-motion support
- responsive typography

Do not sacrifice accessibility for the visual design.

# 22. Performance Requirements

Target an extremely fast local-business site.

### Goals

```text
LCP < 2.5s
CLS < 0.1
INP < 200ms
```

Use:

- Next.js
- optimized images
- lazy loading
- responsive image sizes
- minimal JavaScript
- server rendering where useful
- caching
- compressed assets

The site should feel instant on a normal Kenyan mobile connection.

# 26. Security Requirements

Especially because prescription uploads may eventually involve personal/medical information.

### Requirements

- HTTPS
- secure form handling
- server-side validation
- file type restrictions
- upload size restrictions
- secure storage
- no sensitive information in URLs
- rate limiting
- spam protection
- secure environment variables
- no exposed API keys
- audit logging for sensitive actions

For the **demo**, do not store real patient prescriptions.

Use fictional/demo files.

# 27. AI Chatbot — Make This a Signature Feature

This is where I would differentiate your pitch.

Put:

**“Ask Medivyx”**

in the site header.

The chatbot should answer questions such as:

> What services do you offer?

> Where are you located?

> How can I request medicine?

> Can I send a prescription?

> What healthcare products do you stock?

> How do I contact you?

> What are your opening hours?

### The AI should NOT

- diagnose patients
- prescribe medication
- change dosages
- guarantee drug availability
- provide unsafe medical advice
- pretend to be a doctor/pharmacist

For medical questions:

> “I can provide general information, but a qualified healthcare professional should assess your specific situation.”
